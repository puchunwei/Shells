# ccswitch 首版落地与用户案例

日期：2026-10-16。状态：0.6.0 首版已在本机实现、安装和验证；会话隔离留待后续。

## 推荐范围

首版做两个日常入口：切换配置、编辑槽位。一套配置保存地址、认证、启动选择、Opus/Sonnet/Haiku 映射、子代理默认和额外模型菜单。每套连接先维护一份组合。

```bash
ccswitch use              # 选择公司、个人、备用等配置
ccswitch use work         # 直接切换
ccswitch slots            # 编辑已识别的当前配置的槽位
ccswitch slots edit work  # 直接指定编辑对象
```

配置按名称保存，不设固定的“三套”数量限制。三个基础槽位是 Claude 别名映射；额外模型放进 `/model` 菜单，不另造槽位别名。菜单已有 12 项和第 13 项热新增实测，容量不承诺无限。

当前会话选择 Opus 或 Sonnet 仍用 Claude 自己的 `/model`。`ccswitch slots` 负责修改和保存这些档位对应的模型；两种动作在帮助中用例子说明。

## 用户怎样操作

首次使用，在将要运行 Claude 的机器上导入旧配置：当前 settings 保存为 current，旧默认快照保存为 default。迁移只创建缺失项，保留原值及源文件，不应用模板，不自动切换。自定义 `CLAUDE_CONFIG_DIR` 时读取对应目录；本机和 cloudcli-ssh 远端分别迁移。

添加其他网关时执行`ccswitch add work`，填写地址、认证类型、密钥和模型。录入向导提供统一填充和分别设置；模板只用于新建。结果先保存到配置库，用户可以明确选择保存并应用。

切配置时，选择名称，显示目标机器上的文件路径及脱敏变更摘要，应用该套连接和完整模型设置。保留 hooks、MCP、插件、权限和其他偏好。认证互换时必须显式清空旧认证字段，不能只删除字段。

编辑槽位时，选择 Opus、Sonnet、Haiku、启动选择、子代理或额外模型菜单，查看变更后选择保存、保存并应用或取消。保存只更新配置库。无法确认全局当前项时先要求选择对象，不猜测；编辑未应用配置时也不自动切换。

## 用户案例与验收

| 用户案例 | 操作 | 期望结果 |
| --- | --- | --- |
| 升级后继续用原配置 | 首次执行新版写操作 | 分别生成 current/default；认证、固定模型、独立旧槽位保留；迁移不改源文件 |
| 公司、个人、备用来回切 | `use work`、`use personal`、`use backup` | 地址、认证、槽位、菜单一起切换；切回恢复各自保存值 |
| 只调整 Sonnet | `slots` → Sonnet → 新模型 → 保存并应用 | Opus/Haiku 及固定 ID 菜单项不随之改写；跟随 Sonnet 的引用解析为新值 |
| 当前会话选 Opus 档位 | Claude 内 `/model opus` | 当前会话选择改变；不会自动改写命名配置 |
| 新增 DeepSeek 备用入口 | `slots` → 额外模型菜单 → 添加 | `/model` 可显示候选；启动模型和三个基础映射保持原意；不宣称网关已验证支持 |
| 运行中更换连接或映射 | `use` 或保存并应用 | 报告文件已应用；原生热加载有延迟；当前固定模型 ID 需用 `/model` 重选 |
| 不同网关用不同认证 | Bearer 配置切换至 API Key 配置 | 后续请求使用目标认证，旧认证字段被明确清空 |
| 手动编辑过 settings | 再运行 `status` 或 `slots` | 标记文件偏差；先确认对象或显式保存，不用旧记录覆盖用户修改 |
| 写错配置或操作后想恢复 | `undo` | 恢复上次应用前的受管字段；后加的 hooks 等保留；受管字段另有变化时拒绝盲目覆盖 |
| 在 cloudcli-ssh 中使用 | 登录目标远端后操作远端安装的 ccswitch | 只管理该远端配置；修改 beaver 不冒充远端已更新 |
| 离线或网关不可用 | 保存、选择或查看状态 | 本地功能可用；配置已保存不显示成服务在线，网关错误不触发自动切换 |
| 两个终端想同时用不同连接 | 首版两次 `use` 都会写共享目标 | 明确说明范围；下一阶段用 `run work`、`run personal` 提供独立覆盖 |

## 怎样分步落地

1. **先做兼容和数据层。** 独立配置库，保存认证类型及完整模型字段，幂等迁移 current/default，修复旧快照 API Key 丢失。不同机器独立处理，重名不覆盖。
2. **再做两个操作入口。** 在现有后端增加配置管理和受管字段应用，共用字段清单；bash/zsh/fish 包装层负责当前 shell 同步。交互提供草稿、变更预览和取消；应用使用锁、最新文件合并、原子替换及恢复记录，状态区分保存与应用。
3. **最后完成端到端验收。** 在临时配置目录和模拟网关中观察真实请求的地址、认证头和 model；覆盖旧数据往返、热加载、失败及撤销。分别验证远端和本机版本、三种 shell。真实网关可调用性另行验证；模拟成功不代替线上可用。

首版成功标准：用户原配置可继续使用，三套配置来回切换无字段残留，每套槽位分别保存，能理解动态生效的边界。

下一阶段交付 `run` 会话隔离；同一连接多套模型组合按实际需求再增加。完整账号环境隔离另行设计。

## 已有依据

地址、Token、别名映射及菜单热更新已在 Claude Code 2.1.261、2.1.296、2.1.301 上用模拟网关验证。修改启动主模型不会强制改变运行中当前选择；删除旧认证值还可能在运行进程中残留。因此首版采用原生配置和热加载，输出严格区分文件应用与会话状态。

见[验证报告](../research/2026-10-16-claude-config/README.md)、[完整设计](2026-10-15-ccswitch-multi-profile-product-design.md)。首版多配置功能已经实现并通过本机验收，见[交付记录](../verification/2026-10-16-ccswitch-local.md)；模拟验证不代表真实网关模型均可用。
